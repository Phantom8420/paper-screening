Sparse Attention Windows for Summarizing Long Technical Reports

Transformer summarizers handle a few thousand tokens, but technical reports run to tens of thousands. We restrict attention to a sliding window plus a small set of section-heading tokens that every token can see. Memory then grows linearly with length, and on a set of 2,000 engineering reports the summaries score 2.3 ROUGE-L points above a model that truncates the input.


summarization, transformers, sparse attention, long documents



Introduction
Self-attention compares every token with every other token , so memory grows with the square of the input length. Pretrained encoders such as BERT  therefore stop at 512 tokens, and summarizers built on them read only the start of a long report. In engineering reports the findings are often near the end.

Method
Each token attends to the 256 tokens on either side and to every section-heading token in the document. Heading tokens attend to everything. This keeps the report’s structure visible from any position at a cost that grows linearly with length. The decoder is unchanged. We fine-tuned for 40,000 steps with Adam  and dropout  of 0.1 on 2,000 reports with author-written executive summaries.

Conclusion
Letting every token see the section headings is a cheap way to give a sparse-attention summarizer the structure of a long report. It needs no change to the decoder and fits on a single GPU for reports of 32,000 tokens.
